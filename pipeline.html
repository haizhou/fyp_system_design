Step 2.1
Agent Strategy Planning
SaulLM analyses the structured query and selects a beam search strategy based on anchor count, relation structure, and complexity. [175] StructGPT[177] KSL[186] AgentTuning
① Single-source Beam Search
One anchor entity. Expands hop-by-hop along specified relation chain. At each hop, candidates scored and pruned to Top-K.
Trigger: single anchor entity, linear chain query
Use case: explicit chain queries, single-entity relation lookup
② Multi-source Beam Search [38] KagNet
Multiple independent anchors expand simultaneously. When paths from different anchors reach the same KG node, that node's combined score rises — it naturally enters the beam's top candidates.
Trigger: multi-entity joint constraint query
Use case: supplier × contract × department cross-constraint queries
③ Sub-problem Decomposition
Complex multi-condition queries (containing AND / ALSO). Each sub-condition runs independent beam search; candidate sets are merged and cross-validated.
Trigger: AND / ALSO connectives, or multi-source max-hop exceeded
Fallback when multi-source exceeds max-hop threshold with no convergence

Step 2.2 — Strategy Error Recovery
⚠ Error 1 — Should multi-source, chose single
Dead-end backtrack fails → low confidence → auto-switch to multi-source or LLM fallback.
⚠ Error 2 — Should decompose, chose multi-source
Exceeds max-hop with no convergence → auto-downgrade to sub-problem decomposition.
✓ Error 3 — Should single, chose decompose
Extra sub-problem created. Merge detects overlap → auto-deduplication. No wrong result.
Strategy errors are self-correcting, not catastrophic.

Dead-end Recovery & Confidence Propagation
Graceful fallback when beam paths cannot be extended; three-tier confidence carried throughout the full pipeline. [185] KD-CoT[130] Mallen et al.[39] Knowledge Neurons
Step 2.4 — Dead-end Recovery
🔍
Detection: A Top-K beam candidate has no outgoing edges along the required relation type at the current hop depth.
↩️
Backtrack: Mark path as dead. Pop to next candidate in the beam's Top-K queue.
⚠️
All Top-K exhausted: Mark full path as low confidence. LLM generates a supplementary answer from parametric knowledge.
🏷️
Mandatory labelling: LLM fallback answer is explicitly tagged "not verified in KG." It does not contribute to the KG-supported confidence score.
Step 2.5 — Three-tier Confidence Propagation
Markers assigned in Step 1 — updated in Step 2 — enforced in Step 3 — surfaced to user in Step 4. Never discarded.
High Confidence
Complete path found in KG. All entities are verified real KG nodes. All relations exist as confirmed edges. No proxy nodes, no LLM-supplied gaps. Answer presented directly.
Medium Confidence
Path contains ≥1 semantic proxy node. Structural reasoning is sound but one or more entities are approximated via R-GCN neighbourhood aggregation, not anchored to a verified real KG entity. Labelled: "part inferred via semantic proxy."
Low Confidence
No complete KG path found. Answer relies on LLM parametric knowledge fallback. Explicitly marked: "not verified in KG, for reference only." User can distinguish KG-backed facts from model-inferred content.

Step 3
Candidate Answer Verification
Hard filtering — ensures the final answer strictly satisfies all conditions. Separate from and complementary to beam search soft scoring. [14] LAMA[123] Shaobo et al.KG-GNN-DPO coursework
3.1 Answer Type Check
Does the candidate node's entity type match the answer_type specified in Step 1.1?
Type matches → proceed to constraint check
Type mismatch → discard candidate
Prevents path terminating at wrong entity type — e.g. stopping at Contract when answer_type = Supplier (path too shallow).
3.2 Full Constraint Validation
All constraints from the structured query checked against candidate node attributes. All must pass.
contractValue > £50M
sector = IT
supplierType = SME
jurisdiction = UK
year = 2021
Any single violation → candidate immediately discarded.
3.3 Soft vs. Hard — Responsibilities
Beam Search — Soft Scoring
sConstraint guides the search direction at each hop. A preference signal — not a binary gate. Intentionally allows low-scoring paths to be explored until explicitly filtered.
Step 3 — Hard Filtering
answer_type check and full constraint validation are binary gates. No soft-score approximation can pass a candidate here — exact match required.
3.4 Post-filter Output
✓ Candidates remain
Sort by path completeness, KG verification degree, and confidence score. Pass ranked list to Step 4 for answer generation.
✗ All filtered out
LLM fallback — generates answer from parametric knowledge. Mandatory label: "not verified in KG."
Three-layer guarantee: soft guide → hard filter → confidence label.

SaulLM acts as answer generator, receiving verbalised KG evidence alongside the original question:

Instruction: Answer based strictly on the evidence above.
High confidence mode: LLM may not introduce content beyond KG evidence.
Low confidence mode: Parametric knowledge supplements, but the addition is explicitly labelled as unverified.
